# 2026-10-10 宽面板对角块的分块求解（可选，`VSDLSS_SOLVE_TRI_BLK`）

基于 `perf/blas-tree-branches-20261010`（PR #34）。默认关闭；不设环境变量时所有结果与之前逐位相同。

## 问题

宽面板的对角三角块有两处只能由一个线程做：

1. **内置内核的回代**。外部行部分是八列一组的 SIMD 点积，三角块却是逐列的标量循环：
   第 j 列是一条按行升序的累加链 `x[j] = (x[j] - Σ_{r>j} L(r,j)·x[r]) / L(j,j)`。
   一条链受加法延迟限制，单线程就比前代慢一倍多；链之间又有依赖，团队也拆不开。
   根分隔子面板没有外部行，整块都是这个循环。
2. **BLAS 构建**。前代和回代都是一次 `dtpsv`，单线程（PR #34 里“树干单线程”的那部分）。

单个压缩面板、无外部行，对角块求解一次的时间（1 线程，µs）：

| 宽度 | 内置前代 | 内置回代 | `dtpsv` 前代 / 回代 |
|---:|---:|---:|---:|
| 256 | 5.7 | 21–24 | 7.5 / 10.9 |
| 1024 | 165 | 334–381 | 149 / 156 |
| 2154 | 651 | 1576 | 676 / 682 |

## 做法

思路来自 CKTSO（arXiv:2411.14082）第 V 节对稠密角的处理：切成片，矩形部分并行，小三角块串行。
这里是稠密压缩面板上的版本。

**回代。** 列从底部起按 B 列一块（块边界在 B 的整数倍处），块内再从底部起八列一组。
对块 [jb, je) 中组 [g0, g1) 的第 j 列：

```
x[j] = (((x[j] - Σ_{r ≥ je} L(r,j)x[r]) - Σ_{g1 ≤ r < je} L(r,j)x[r]) - Σ_{j < r < g1} L(r,j)x[r]) / L(j,j)
```

三个和各自按行升序。第一个和只读已完成的块，所以一个块的各列可以同时算：
内核一次算八列（每列一条独立的链，新内核 `vsdlss_simd_tri_dots_packed`），不同的列区间交给不同线程。
后两个和留在一个线程上。项与默认循环相同、顺序不同，所以**结果与默认内核有舍入差别，并且依赖 B**；
不依赖线程数、不依赖是否有 AVX2、不依赖列如何分组（每列一条链）。

**前代**（只影响 BLAS 构建）。64 列一块：块内逐列，块以下的行按列升序减去该块各列，行区间交给不同线程。
每个分量的运算和顺序就是内置前代内核的，所以结果与内置内核逐位相同（BLAS 构建里不再是 `dtpsv` 的舍入）。
非 BLAS 构建的前代不变。

**团队从哪来。** 调用者所在的团队在跑任务时（树顶按分支、树顶团队的 `single`），用子任务把一步分给**此刻空闲**的线程；
否则在 `vsdlss_parallel_width` 允许时自己开一个团队。一个块的共享步骤达到 `VSDLSS_SOLVE_TRI_WORK`（默认 16384 次乘加）才拆。

“此刻空闲”由树顶团队的忙线程计数给出（`vsdlss_parallel_helpers`，每个分支任务开始时加一、结束时减一）：
只有树顶收窄到分支数少于线程数的地方（树干）才会把步骤分出去。第一版只要在任务团队里就拆，
在 900² 网格的 BLAS 构建上 2 线程反而慢了 20–30%（50 → 61–72 ms）：各线程都在忙自己的分支，
子任务要等别人有空才被取走，调用者做完自己那片后只能睡着等。改成按空闲线程数之后回归消失（见下表）。

开关：`VSDLSS_SOLVE_TRI_BLK=<B>`（列数，按 8 取整；0 或不设为关闭），或全局 `vsdlss_solve_tri_blk`。
对宽度 ≥ 16 的压缩（M3）面板生效；BLAS 构建里对角块不再调用 `dtpsv`，外部行的 `dgemv` 不变。

## 实测

2 核 Xeon 2.10 GHz 云容器，GCC 13.3 `-O2 -fopenmp`，OpenBLAS 0.3.26 单线程；噪声约 ±15%。

单个面板的对角块（无外部行，B = 128，µs）：

| 宽度 | 回代：默认 | 回代：分块 1T | 回代：分块 2T | 前代（BLAS 构建）：`dtpsv` | 分块 1T | 分块 2T |
|---:|---:|---:|---:|---:|---:|---:|
| 256 | 21–24 | 8.5–9.0 | 同左（不拆） | 7.5 | 7.0–7.9 | 同左 |
| 1024 | 334–381 | 137–149 | 86–99 | 148–175 | 146–176 | 122–150 |
| 2154 | 1576 | 673–791 | 371–425 | 666–726 | 668–740 | 483–590 |

- 回代：单线程快约 2.3 倍（去掉了延迟受限的标量链），2 线程再快 1.7–1.9 倍。
- BLAS 构建的回代：单线程与 `dtpsv` 持平，2 线程快 1.7–1.9 倍。
- 前代：单线程与 `dtpsv` 持平，2 线程只有 1.2–1.4 倍。原因没有查清（试过预取和按缓存行切分行区间，前者无效已撤回，后者保留）。

整个核心求解 `vsdlss_sn_solve_inplace`（网格 + AMD + 松弛超节点，4 轮最小值，ms）：

| 网格 | 构建 | 默认 1T | 分块 1T | 默认 2T | 分块 2T |
|---|---|---:|---:|---:|---:|
| 3D 32³ | 内置 | 6.94 | 5.68 | 5.32 | 3.77（1.41×） |
| 3D 32³ | BLAS | 5.73 | 5.65 | 3.99 | 3.37（1.18×） |
| 3D 24³ | 内置 | 1.73 | 1.57 | 1.36 | 1.22（1.12×） |
| 3D 24³ | BLAS | 1.59 | 1.53 | 1.16 | 1.20（噪声内） |
| 2D 300² | 内置 | 3.78 | 3.83 | 2.80 | 2.73（噪声内） |
| 2D 300² | BLAS | 4.02 | 3.67 | 2.40 | 2.36（噪声内） |
| 2D 600² | 内置 | 34.7 | 33.3 | 20.0 | 18.1（噪声内；B=64 时 15.5） |
| 2D 600² | BLAS | 32.0 | 32.8 | 16.6 | 17.7（噪声内） |

**收益集中在 3D 类问题（宽分隔子）上；2D 电源网类算例上测不出差别。** B = 64 与 128 没有可分辨的差别。

上表是“只在有空闲线程时才拆”这条规则之前测的。加上规则后重测（B = 128，2 线程）：32³ 内置 5.06 → 4.00 ms、BLAS 4.20 → 3.85 ms；
24³ 内置 1.40 → 1.11 ms、BLAS 1.20 → 1.10 ms；600² 内置 15.9 → 14.8 ms、BLAS 14.4 → 12.2 ms（噪声内）。

## IBM 电源网格基准

沙箱访问不了 UCSB 的下载页，只从一个公开 GitHub 仓库拿到了最小的 **ibmpg1**（网表与参考解）；ibmpg2–6 没有测。

ibmpg1（`bench_ibmpg`，AMD）：未知量 16 327，5 个分量，核心 11 777，面板 4566 个，最宽 57 列；
L 的元素 76% 在外部行，宽度 ≥ 16 的面板的三角块只占 7.6%。

| | 默认 | `VSDLSS_SOLVE_TRI_BLK=128` |
|---|---:|---:|
| 整个求解（`bench_ibmpg`，1 / 2 线程） | 0.4 / 0.3–0.4 ms | 0.3–0.4 / 0.3–0.4 ms |
| 最大分量核心前代+回代（`bench_phase`，1 线程，内置） | 0.23–0.26 ms | 0.18–0.24 ms |
| 与 IBM 参考解的最大偏差 | 6.06e-6 V | 6.06e-6 V |
| 后向误差 | 1.3e-16 | 1.3e-16 |

**测不出差别**，也不该有：受影响的三角块只占 L 的 7.6%，即使这部分快一倍，核心求解也只快 2% 左右。

用与 ibmpg2、ibmpg3–6 规模相近的二维网格（360²、900²，同样经 `vsdlss_factorize_m3`）代替更大的用例：

| | 360²（13 万） | 900²（81 万） |
|---|---:|---:|
| 最宽面板 | 546 | 1452 |
| L 中外部行占比 | 84.3% | 85.4% |
| 宽度 ≥ 16 的面板的三角块占 L | 10.4% | 10.6% |
| 其中宽度 ≥ 256 | 2.8% | 5.6% |
| 核心求解 2 线程，内置：默认 → 分块 | 4.7–4.8 → 4.3–5.0 ms | 61–67 → 59–64 ms |
| 核心求解 2 线程，BLAS：默认 → 分块 | 4.2–5.0 → 3.9–4.3 ms | 50–64 → 48–56 ms |
| 回代树顶（内置，2 线程） | | 6.1–6.8 → 4.0–4.1 ms |

二维网格上三角块只占 L 的一成左右，分块求解对整个核心求解的影响在噪声内（几个百分点以内）；
能看清的只有回代树顶那一段（900²：约 6.5 → 4.0 ms）。真实的 ibmpg2–6 是多层网格并有 VDD/GND 多分量，
结构上接近这类二维网格，预计结论相同，但**没有实测**。

## 未验证与风险

- **2 线程以上没有实测。** 串行部分约占一个面板的 B/w（w = 2154、B = 128 时约 6%）。
- **ibmpg2–6 没有实测**（见上节）。
- **客户电源网格用例、METIS 排序、MKL 未测。** 2D 网格上没有收益，电源网类用例预计相近。
- **`OMP_WAIT_POLICY=passive` 下可能变慢。** 每个块要唤醒一次等待中的线程；单面板基准上 passive 时 2 线程比 1 线程慢
  （一次测量：前代 983 对 737 µs，回代 830 对 794 µs）。
- 默认关闭，因为它改变舍入；打开后同一个 B 下各线程数结果逐位相同。是否作为默认需要另行决定。
- TSan 未跑。

## 测试

- `test_simd`：新点积内核与标量链逐位相同。
- `test_solve_kv`：19 种宽度 × 3 种外部行数 × 5 种 B。回代与测试里按文档顺序独立写的标量实现逐位相同，
  与默认内核的相对差 < 1e-12，2/4 线程与 1 线程逐位相同；前代与默认内核逐位相同（BLAS 面板除外）；坏主元和非有限值的状态码与默认内核一致。
- `test_supernodal`：16³ 网格在 B = 16/64/128 下，各线程数、各树顶调度与 1 线程逐位相同，残差达标，
  并用计数器 `vsdlss_sn_panel_tri_splits` 确认团队确实分担了宽面板的步骤。
- `make test-supernodal` 多跑一遍 `VSDLSS_SOLVE_TRI_BLK=16 VSDLSS_SOLVE_TRI_WORK=1`（全部矩阵，最小的块也拆成任务）；BLAS 构建再多一遍。
- `make test`、`make BLAS=1 test`、`make sanitizers` 通过；BLAS 构建的两个测试另用 ASan/UBSan 跑过；无 OpenMP 构建通过。
- 变异检查：列区间漏列、行区间漏行、块大小随团队变化、去掉 `taskwait`、点积内核换序、组内累加换序、树顶团队不设任务团队、
  忙线程计数永远显示全忙，8 个改坏的版本全部被抓到；把一组八列拆成两次调用（等价改写）不触发任何失败。
