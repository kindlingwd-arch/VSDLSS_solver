# 单 RHS 回代：≥32 列面板（2026-09-27）

环境同 `solve-narrow-panels-20260927.md`：1 vCPU KVM（Xeon @ 2.10GHz，L2 2 MB，L3 260 MB），GCC 13.3，`-O2`；
8M 双网（平均度 2.5）、AMD、1 线程。单核流式读带宽实测 13–15.6 GB/s。本机时段噪声大（同配置完整求解 0.57–0.63 s），
结论只取同进程内轮换的配对比值。

## 1. 8M 上这部分有多大、瓶颈是什么

在完整求解内部对 ≥32 列面板计时（`-DVSDLSS_PROF_BACK`）：

| 回代桶 | 调用 | ms/次求解 |
|---|---:|---:|
| 32–63 | ~1750 | 18.4–19.7 |
| 64–255 | ~610 | 31.3–33.7 |
| 256–511 | 41 | 14.7–15.7 |
| ≥512 | 16 | 19.0–19.7 |
| 合计 | | 83–89（完整求解的约 14%） |

把这些面板导出后单独重放（配对比值，以当前内核为 1）：外部点积 0.57–0.63，对角三角块 0.31–0.41，两者之和≈1。
按导出数据算，≥32 桶外部块乘加 8.04e7、三角块 1.54e7，回代需读约 770 MB 因子：

- 外部点积受带宽限制：同一面板在缓存里重复跑，每次比冷数据快 2–3×；冷数据下 64–255 桶约 9.9 GB/s，接近本机流式上限。
- 三角块受延迟限制：每步约 0.9 ns（一次减法延迟），为保持逐位一致，第 j 行必须按 r 升序依次减，整块是一条长度约 w²/2 的链。

## 2. 试过的方向

| 方向（逐位一致，除注明外） | 结果 |
|---|---|
| 外部点积 16 列一组、4 个独立累加器（dot16） | 冷数据不快（0.98–1.1×），热数据 ≈ dot8；瓶颈不在指令 |
| 外部点积软件预取（32/64/128 行） | 更慢 |
| 预打包去掉运行时转置 | 未实现：只省洗牌指令，不减字节；而 ≥32 桶外部块副本约 +640 MB（因子 1.28 GB 的一半） |
| **三角块与外部点积交错（`vsdlss_simd_back_fused`）** | 采用，见下 |
| 三角块 16 路部分和（**不逐位一致**，相对差 4.2e-15） | ≥32 回代 −14%，完整求解 −1.7%；与交错法收益相当且改变结果，不采用 |

交错法：外部点积按 8 列一组自上而下推进，游标可超前；三角块第 j 行开始前保证其所在列组已算完；
每做 K 个三角项插入一个 4 行点积步，让带宽受限和延迟受限的两类工作重叠。每个输出的运算顺序不变。
出现非有限值或非法主元时，恢复 z_J 并走原路径，状态码和 x 与原来完全一致。

## 3. 8M 结果（`bench_solve_back`，参考为原内核 `VSDLSS_SOLVE_V2=3`，每次解逐位核对）

| | 第 1 次（21 轮） | 第 2 次（21 轮） | 第 3 次（15 轮，带计时） |
|---|---|---|---|
| 完整求解配对比值 | 0.980 | 0.992 | 0.982 |

面板内计时（第 3 次）：64–255 33.7 → 30.1 ms（−11%），256–511 15.7 → 13.2 ms（−16%），≥512 19.7 → 17.8 ms（−10%），
32–63 基本不变（因此默认 `VSDLSS_FUSE_MIN=64`）。K 取 8/16/32 差别在噪声内（完整求解 0.973/0.985/0.988），默认 16。

## 4. 结论

- 在保持逐位一致的前提下，8M 上 ≥32 列回代的常数级空间很小：约 14% 的求解时间里，大半是读因子的带宽成本。
  交错法拿到其中约 10%，完整求解约 1–2%。
- 继续提速必须减少字节，而不是减少指令：单精度存储 L（此前误差实验 3.2 µV）、多线程分摊带宽，或者在
  服务器上利用前代刚读过的树顶面板仍在缓存中的机会。这些都超出本轮的内核范围。
- 本机 L3 260 MB，树顶面板在同一分量的前代之后多半仍在 L3；小 L3 的笔记本（如 i7-1260P，18 MB）上外部点积会
  更偏带宽，交错收益可能更小，需要实测。多线程未测。
