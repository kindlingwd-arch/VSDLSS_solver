# P1-2 小块 selective inversion（2026-09-28）

分支 `perf/selinv-20260928`，基于 `perf/solve-ledger-kernels-20260927`（第 25 篇）。原始日志在 `docs/benchmarks/selinv-20260928/`。

## 结论

**本机单线程、单右端项的瞬态求解中，对角块求逆没有可用收益，不建议默认启用。** 最好的配置（w≥7 全部求逆）在 4M 上核心回代 −4.6%、求解 −1.3%，却需要 1.48 s 一次性求逆，约 530 步才回本；只逆 7–31 列时变化在噪声内；逆 1–6 列反而慢 4%。

原因：第 25 篇把 7–31 回代的剩余瓶颈归于对角三角的串行依赖，这只在**热缓存**下成立（微基准回代快 1.5–1.75×）。完整求解中面板按顺序流过内存，回代受带宽限制，串行依赖被乱序执行与访存等待重叠掉，冷缓存下只剩 1.03–1.19×。求逆不减少读取的字节数，因此拿不到带宽上的收益。

保留为实验 API（`vsdlss_m3_selinv`，默认不调用），供多右端项、多线程或更高带宽机器上复测。

## 实现

```c
vsdlss_status vsdlss_m3_selinv(vsdlss_m3_factor *f, long long wmin, long long wmax);
```

- 对宽度在 [wmin, wmax] 的核心超结点面板，把对角块 L_JJ 原地换成 M = L_JJ⁻¹（LAPACK dtrti2 次序），上三角部分置零。**不额外占内存**；代价是一次 Σw³/3 flop。
- 前代：x_J = M b_J（四列融合 axpy），外部行更新同 KV=2（w≤128 寄存器分块，更宽用 128 行分块四列融合）。
- 回代：外部部分同 KV=2（dot8），然后 x_J = Mᵀ v_J，每列一个独立点积、8 列一组，块内不再有串行依赖。
- 不可逆：之后求解走串行面板调度（不走树并行），`vsdlss_sn_export_L` 返回 INVALID，重复调用返回 INVALID。磁盘模式返回 INVALID。
- 结果不再与三角求解逐位一致，只在舍入范围内一致。

- 1M ≥7 的第二轮明显偏慢（整轮所有阶段同步变慢），视为机器噪声，两轮分列。两轮同配置的差异约 1–2%，小于这个量级的变化不下结论。
- 1–6 列变慢：这些面板原本走生成的专用小核（`vsdlss_small_solve.inc`），通用求逆核在极小块上开销更大。
- 宽度桶（级别 2，1M）：7–31 回代 9.28 → 8.50 ms（−8%）、前代 7.52 → 7.16 ms，折合整次求解约 −2%，在完整求解的噪声以内。
- 精度：4M 全部求逆时后向误差 4.8e-17，与三角求解（5.0e-17）同量级；测试中 3D 网格（最宽 1351 列）全部求逆，相对差 3.4e-15。

## 对路线表的回答

- 「只选可摊销的对角块」：按摊销算，4M 只有 ≥7 全部求逆有正收益，约 530 步回本；7–31 单独求逆 setup 很便宜（0.05 s），但收益测不出来。
- 「加 setup/内存后仍划算吗」：内存不增加；setup 从 0.05 s 到 1.5 s；单右端项单线程下**不划算**。
- 可能划算的场景（未测）：多右端项 / 多次求解共享同一面板（`vsdlss_m3_solve_many`，面板在缓存中复用时热缓存倍数 1.5–1.75× 生效）；带宽更高、每核带宽更充裕的机器。多线程下每核带宽更少，预计更不划算，但树并行路径本来就不支持求逆面板。

- 新增 `test_selinv`（加入 `make test` 与 `make sanitizers`）：2D 网格（多分量、窄面板）与 3D 网格（最宽 1351 列，外部行 >1024），宽度区间 7–31、1–6、全部、32–127、≥128；原编号、packed、原地、多右端项求解，1 与 4 线程；与三角求解相对差 <1e-12，后向误差不超过三角求解的 4 倍；非有限 RHS、`export_L` 拒绝、重复调用与非法区间。`VSDLSS_SIMD=0` 下同样通过。
