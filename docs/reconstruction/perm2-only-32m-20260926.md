# Standalone gather and write-back scaling, 8M–32M (2026-09-26)

The requested experiment isolates global-to-packed gather and packed-to-global
write-back. It does **not** generate a power-grid matrix, factor it, perform
triangular solves, or measure the full M3 solve API. The input is a seeded,
shuffled bijection and one double vector. Vertex degree and SPD structure do
not affect this isolated memory movement experiment.

`test/bench_perm2_only.c` models the direct loops and the two-pass bucket
algorithm of `src/vsdlss_m3.c`, with the same 32768-element destination blocks,
per-thread bucket ranges, 16-bit block offsets, dynamic block scheduling, and
finite-value check during gather. It uses a plain 32-bit global-to-packed
inverse instead of M3's component/local encoded inverse. One-time permutation
and plan construction are excluded from timings. Each method uses a prebuilt
plan, a warmed buffer, alternating order, and eight samples; output from both
methods is compared bitwise to the original vector before and after timing.

The VM had an 8 GiB cgroup memory limit and 8 CPU quota. Times are medians in
milliseconds, one process per row. These are observations on this shared VM,
not predictions for the eventual server.

| Nodes | Threads | Direct gather | Two-pass gather | Direct write-back | Two-pass write-back |
|---:|---:|---:|---:|---:|---:|
| 8M | 4 | 26.161 | 19.047 | 24.148 | 19.782 |
| 16M | 4 | 37.543 | 37.253 | 39.663 | 37.711 |
| 32M | 4, run 1 | 81.549 | 62.614 | 79.568 | 63.264 |
| 32M | 4, run 2 | 77.906 | 62.679 | 83.643 | 60.994 |
| 32M | 8, run 1 | 61.832 | 37.858 | 51.841 | 37.793 |
| 32M | 8, run 2 | 63.067 | 38.635 | 52.390 | 38.794 |

For 32M and four threads, the two-pass sum is 123.7–125.9 ms, versus
159.5–161.5 ms for the two direct phases. With eight threads, the two-pass
sum is 75.7–77.4 ms. The timings exclude conversion or a caller's work
surrounding those phases. The result does not imply a full solve speedup of
the same fraction, because that includes core triangular work and low-degree
replay. The microbenchmark does not capture component boundaries, M3 workspace
ownership, or competition for bandwidth with the rest of a solve.

Reproduce on a clean build:

```sh
make bench_perm2_only
./bench_perm2_only 8000000 4 8
./bench_perm2_only 16000000 4 8
./bench_perm2_only 32000000 4 8
./bench_perm2_only 32000000 8 8
```

Before this isolated probe, the 32M, mean-degree-2.5 full-factor benchmark
successfully assembled 40M edges, but factorization exceeded the VM's 8 GiB
limit. That failure has no bearing on the isolated vector movement numbers.
