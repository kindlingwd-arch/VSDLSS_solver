# 2026-10-18 ECO 低秩修改：`vsdlss_m3_modify`

## 结论

ECO 改动少量电导或对地电导后，不再重新分解，而是直接把 A 的因子改成 A + ΔA 的因子。

在 252 万结点的合成网格上（`grid:600:3`，METIS 排序，4 线程，WSL2 笔记本）：

| 每次 ECO 的规模 | 修改耗时（中位数） | 重新分解 | 加速 |
|---|---|---|---|
| 1 条电导 | 5.1 ms | 3.0 s | 592 倍 |
| 10 条电导 + 5 个对地修改 | 28 ms | 2.8 s | 100 倍 |
| 100 条电导 + 50 个对地修改 | 179 ms | 2.9 s | 17 倍 |
| 10 + 5，AMD 排序 | 61 ms | 1.7 s | 28 倍 |

- 一次热求解约 30–37 ms。每次 ECO 只改 10 条电导左右时，修改的耗时和一次求解相当。
- 每个分量的第一次修改要建索引，耗时约为中位数的 2 倍（`bench_eco` 输出里的 "first"）。
- 精度：连续 20 次 ECO 后，对 A + ΔA 的后向误差为 2.6e-16–3.5e-16，和重新分解相当（2.6e-16–3.0e-16）。两者的解相差 3e-15–8e-15（相对值）。
- 修改后的求解速度不变，修改不会改变因子的结构。

## 1. 接口

```c
typedef struct vsdlss_m3_modify_stats {
    csi updates, downdates;             /* 实际执行的秩 1 项 */
    csi record_columns, core_columns;   /* 改写的因子列数（含重复） */
} vsdlss_m3_modify_stats;
vsdlss_status vsdlss_m3_modify(vsdlss_m3_factor *factor, csi nz, const csi *row,
                               const csi *col, const double *delta,
                               vsdlss_m3_modify_stats *stats);
```

- ΔA 是对称矩阵，用调用者编号下的三元组 `(row, col, delta)` 给出。上、下三角都可以写，重复的项会相加。
- 结点 a、b 之间的电导改变 dg：传 `(a,b,-dg)`、`(a,a,+dg)`、`(b,b,+dg)`。
- 结点 a 的对地电导改变 dg：传 `(a,a,+dg)`。
- 非对角项只能落在因子已有的结构上，也就是只能修改原有元件。新增的连接会改变结构，返回 `VSDLSS_ERR_UNSUPPORTED`，这时需要重新分解。
- 全有或全无：出错时因子完全不变。
  - `VSDLSS_ERR_NOT_POSDEF`：A + ΔA 不正定，或者数值上已接近不正定；
  - `VSDLSS_ERR_UNSUPPORTED`：结构改变、跨连通分量的连接、磁盘模式；
  - `VSDLSS_ERR_OOM`：内存不足；
  - `VSDLSS_ERR_INVALID`：参数错误。
- 打包顺序和 slots 不变，`vsdlss_m3_packed_buffer` 可以继续使用。
- 不能和同一个因子上的求解或其他调用并发执行。

## 2. 算法

### 2.1 把 ΔA 拆成秩 1 项

对任意对称矩阵 ΔA，有

ΔA = Σ_{(a,b)} g_ab (e_a − e_b)(e_a − e_b)ᵀ + Σ_i r_i e_i e_iᵀ，

其中 g_ab = −ΔA(a,b)，r_i = ΔA(i,i) + Σ_b ΔA(i,b)。

- g > 0（或 r > 0）是更新，g < 0 是降秩。
- 电导改变正好对应一项 g = dg，对角余项为 0。
- 所有更新先做，降秩后做。这样每个中间矩阵都夹在 A + ΔA 和 A + (ΔA 的正部) 之间：只要结果正定，中间每一步也都正定。

### 2.2 一个分量的因子是一次完整的 Cholesky 分解

按消元顺序：低度消元记录在位置 0..count−1，是单位下三角 L 加主元 D 的形式；core 在位置 count + k，是超节点 LLᵀ 形式。

对于秩 1 项 w = e_a − e_b，如果 b 在 a 那一列的结构里，被改动的列就是消元树上从 a 到根的路径，而且结构不变（Davis & Hager 1999）：处理完第 j 列后，剩下的向量一定落在第 j 列的结构里。原有元件 (a,b) 一定满足这个条件，因为 A 的结构包含在 L 的结构里。

- **记录部分**：沿路径逐列执行 Gill–Golub–Murray–Saunders 的 C1 方法（LDLᵀ 的秩 1 修改）。记录的 `pivot` 就是 d，`multiplier` 就是 L 的单位下三角元素。
- **core 部分**：从记录传到 core 的部分，是 core Schur 补上的秩 1 修改 αzzᵀ。在超节点面板上逐列执行双曲旋转，公式与 CSparse 的 `cs_updown` 相同，降秩时用稳定的混合形式。

### 2.3 core 的批量处理（秩 k）

每条路径都要经过 core 消元树顶部的分隔块，这一块是所有路径共用的。

- 一个项的记录阶段只改记录，core 阶段只改 core，两者互不影响。所以先把所有项的记录阶段做完，再把最多 64 项放在一批里处理 core（Davis & Hager 2001）。
- 沿各项路径的并集按列升序处理。每一列上，各项按原顺序依次旋转，每一项都作用在前一项改过的列上。这和逐项执行的运算顺序完全相同，结果逐位一致。
- 每一列先按项依次算出对角元和各项的旋转系数，然后每个下方元素在寄存器里依次完成所有项的旋转。一次处理 4 个元素，让彼此独立的依赖链填满浮点流水线。
- 工作向量只为路径涉及的行分配：一列的行都是它在消元树上的祖先，而祖先也都在路径上，所以行数不超过路径并集的列数。
- 实测（10 条电导 + 5 个对地修改，AMD 排序）：逐项处理 104 ms → 批量 77 ms → 加上 4 元素交错 55–61 ms；换成 METIS 排序后为 28–42 ms（机器波动）。批量 16 / 32 / 64 / 128 在 100 条电导时分别为 200 / 164 / 129 / 121 ms，默认取 64。
- AMD 排序下 core L 共 1787 万个元素，一次 ECO 触及约 570 万；METIS 的分隔块更小，触及的更少。成本主要由树顶分隔块决定，所以生产配置（METIS）更有利。
- 路径总是推进到根：即使某个面板上所有项的值恰好为 0，也继续走到父面板，因为更上方的元素可能已经被子孙面板写入了非零值（与 cs_updown 一致）。

### 2.4 全有或全无

- 每一列在第一次改动前，都会把旧值存进 undo 日志。任何一项失败时，按相反顺序恢复本次调用改过的所有列。
- 失败的情形包括：主元相对损失超过 1 − 1e-14（相当于只剩约 45 个 ulp，视为不正定）、出现非有限值、内存不足。
- 按层调度的尾部（`VSDLSS_TAIL_WINDOWS=0`）的 forward plan 里存有乘子的拷贝，调用成功后会逐条修补。窗口调度（默认）没有这种拷贝。

### 2.5 索引

每个分量第一次修改时，会建一个索引并随因子保存：

- 每 64 条记录存一个邻居偏移的检查点，用来按位置定位记录；
- 没有做求解序重编号的分量（小分量，或 `VSDLSS_RELABEL=0`），另存一张"局部结点 → 消元位置"的表。默认重编号后局部编号就是消元位置，不需要这张表。

线上用例 3300 万条记录对应约 50 万个检查点（约 4 MB）。第一次调用会多花一点时间建索引（上表中 "first" 那一项）。

## 3. 限制

- 只支持不改变结构的修改：原有元件的电导变化、对地电导变化（包括删去一个元件，只要矩阵仍然正定）。新增元件、新增结点需要重新分解。
- 只支持内存模式的 M3。磁盘模式、未打包的记录（单个分量超过 2³⁰ 个结点）返回 `UNSUPPORTED`。
- 修改是单线程的。
- 多次更新/降秩后误差会累积。建议定期用 `vsdlss_backward_error` 检查，必要时重新分解。测试和基准里连续 4–20 轮后都没有可见的误差增长。
- 结果和重新分解不是逐位相同的（运算不同），但精度相同。

## 4. 验证

`test/test_modify.c`（已加入 `make test` 和 `make sanitizers`）：

- 接地电阻网络：两个网格加度为 2 的导线链和悬挂结点、一个小分量，调用者编号随机打乱。
- 每轮修改后检查：对 A + ΔA 的后向误差 < 1e-13，与重新分解的解相对差 < 1e-9。
- 覆盖：
  - 更新和降秩、对地修改、上/下三角写法和拆成两半的重复项；
  - 同一个因子上连续 4 轮修改，其中一轮有 90 条电导 + 20 个对地修改，会触发多次批满提交；
  - 记录列和 core 列；
  - 重编号开/关、窗口调度/按层调度、1/4 线程。
- 按层调度的 forward plan：直接检查每条拷贝的乘子和记录一致。去掉修补后会报 27 处不一致。plan 只在较大规模和多线程下才被回放读取，所以测试用不变量检查而不是求解来覆盖。
- 失败的调用都要求逐位不变：
  - 先有若干合法更新、后有一项使矩阵不正定的降秩 → `NOT_POSDEF`；
  - 跨分量连接 → `UNSUPPORTED`；
  - 越界、NaN、负的个数、NULL 因子 → `INVALID`。
- 分配失败扫描：每个分配点各失败一次，都返回 `OOM` 且因子不变，随后同一调用成功，没有泄漏。
- 对照实验：让修改函数什么都不做时，测试报 70 处失败。
- `-Wall -Wextra -Werror`、`OPENMP=0` 构建、ASan/UBSan 均通过。

`test/bench_eco.c`（`make bench_eco`）：

```bash
ECO_EDGES=10 ECO_GROUND=5 ECO_ROUNDS=20 ./bench_eco grid:600:3 6 4
ECO_EDGES=10 ECO_ROUNDS=20 ./bench_eco text:/path/to/case 6 32     # 真实用例
```

输入可以是 `PG_DUMP` 文件、`grid:SIDE[:CHAIN]` 或 transient_driver 的文本目录。程序依次报告：分解时间、热求解时间、每次修改的耗时和改写的列数、修改后对 A + ΔA 的后向误差，以及重新分解的时间和两种解的差。
