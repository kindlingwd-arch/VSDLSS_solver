## 1. 现状与下限

6100 万结点双网 EMIR 用例，服务器（双路 AMD EPYC 7H12），32 线程，PACKED=0，每步约 165 ms：

| 阶段 | 每步 | 内容 |
|---|---|---|
| 收集 | 34 ms | 用户顺序 → 内部顺序，6100 万个数重排一次 |
| 前代回放 | 40 ms | 读一遍全部低度消元记录 |
| core 求解 | 20–28 ms | 读两遍 core 因子 |
| 回代回放 | 32 ms | 再读一遍全部消元记录 |
| 写回 | 28 ms | 内部顺序 → 用户顺序 |

另外，仿真器每步还要读出 x、组装 b，这部分不在上表内。

结论：

- 求解受内存带宽限制。4 核机器上，core 求解用到了约 95% 的读带宽；回放也是流式读取。
- 在"每步独立解一次 Ax=b"的前提下，下限是把因子从内存读两遍。现在的回放加 core 约 100 ms，基本就是"数据量 ÷ 实际带宽"。
- 换一种直接法的实现，或者从零重写，读的数据量差不多，时间也差不多。
- 迭代法也不行：低度消元产生的填充很少，因子和 A 差不多大，一次求解读的数据相当于一次 A·x，迭代超过 1 次就比现在慢。
- 要突破，只能：减少每次读的字节数；减少读的次数；减少时间步数；提高实际带宽。

## 2. 评估过并放弃的方向

| 方向 | 依据 | 结论 |
|---|---|---|
| 回代侧数据流流水线（`VSDLSS_PIPE_BWD=1`） | 服务器实测 core + 回代 48 → 46 ms/网 | 收益约 1%，保留为默认关闭的开关 |
| 用接口响应 H 解耦局部回放和 core | 4 核实测慢 66%；按服务器估算每网净慢约 14 ms | 负收益 |
| 仿射前缀扫描 | 依赖深度不是瓶颈；运算量和访存约多 2 倍 | 只适合 GPU |
| 串联链一步投影（α、β 分压系数） | 链内的局部解每步随 b 变化，仍要递推；读的字节不减少 | 无收益 |
| 邻居下标压缩到 16 位（`nb_stats`） | 邻居是下一条记录的比例约 0%；16 位以内 23–62%；字节只少 2–7% | 不值得 |
| 对角块预求逆 | 对角块占 L 约 17%（宽度 ≥16 的约 11%）；逆的存储量不变，读的字节不减少 | 无收益，且失去逐位一致 |
| 稀疏右端项零子树剪枝 | 你们实测 b 中只有约 20% 为零，汇集到 core 后基本全部非零 | 不适用 |
| 结构零预处理（恒为 0 的结点） | 最多影响前代的 20%，约 1–4% | 收益太小，暂不做 |
| 分解时同步做前代 | 只省第一次求解的一遍前代（约 50 ms/网，一次性）；回代方向相反，省不掉 | 不做 |
| 编译选项 `-O3 -march=native` | 本机实测无差别（AVX2 内核已按运行时检测选择） | 不需要 |
| 编译选项 `-ffast-math` | 会删掉约 80 处 `isfinite` 检查，并破坏逐位一致 | 不能开 |
| 多线程排序（mt-metis、ParMETIS） | 只影响分解阶段的排序；ParMETIS 排序质量更差，填充增加会让每步求解变慢 | 等分解分项计时后再定 |
| 从零重写求解器、改用迭代法 | 见第 1 节 | 不做 |

## 4. 主方案：求解器接管时间步进 + 跨时间步融合

### 4.1 数学原理

后向欧拉每一步解：

$$
\underbrace{\left(G + \tfrac{C}{h}\right)}_{A\ \text{（固定）}} x_{k+1} = \underbrace{\tfrac{C}{h}x_k + I_{k+1}}_{b_{k+1}}
$$

电容接地时，C 是对角矩阵，所以 $b_{k+1}[v] = \frac{C_v}{h}x_k[v] + I_{k+1}[v]$：**结点 v 下一步的右端项只依赖它自己这一步的电压。**

每一步求解时：

- **前代**按消元顺序，把每个被消去结点的主元值 $s_i$ 推给它的邻居（主元值留在工作向量里，供回代使用）；
- **core 求解**；
- **回代**按相反顺序，由邻居的电压恢复每个结点的电压。

前代和回代都要读同一批消元记录（主元、乘子、邻居下标），约 6000 万条、约 2 GB。

**依赖关系**：

- 一次求解内部，回代必须等前代全部完成。消去树只有一个根，见流水线实验。
- 跨时间步时，第 k+1 步前代一组记录所需的输入，只有这组结点的 $b_{k+1}$，以及组内更早记录推过来的量。而 $b_{k+1}$ 只依赖这组结点的 $x_k$，在第 k 步回代完这组时就有了。

所以可以按组交错执行：一组做完第 k 步回代，马上做这一组第 k+1 步前代。**每个公式都不变，只改变执行的先后顺序，结果可以和逐步求解逐位一致。**

**为什么变快**：一组（尾部连通块）约 700 条记录、约 20 KB，放得进 L2 缓存。回代从内存读一遍，紧接着的前代命中缓存，消元记录每步只从内存读一遍。

**为什么能省掉收集和写回**：求解器解的是 $(PAP^\top)(Px) = Pb$。把整个递推放在重排后的坐标里：

$$
Pb_{k+1} = \frac{PCP^\top}{h}(Px_k) + PI_{k+1}
$$

C 是对角矩阵，$PCP^\top$ 只需在分解时把对角元素换一次顺序。电流源用稀疏列表给出，只需重排有电流源的结点。每步不再需要重排两个完整的向量，只在输出时换回用户顺序。

### 4.2 现有结构中可以利用的性质（已对照代码）

- **块并行段自成一体**（`vsdlss_reduction.c` 约第 2118 行）：块 b 只消去"邻居全在本块内"的结点，记录只读写本块的结点，块与块互不重叠。块里没被消去的边界结点，以后成为尾部主元或 core 结点。
- **尾部单窗口时，连通块之间互不相交**，只通过 core 结点联系。前代对 core 的更新是延后的，按消元顺序补减。
- **前代的主元值留在工作向量里**（`saved` 为 NULL 时），回代直接从那里读取。

由此得到的依赖顺序是：块回代第 k 步 → 块前代第 k+1 步 → 尾部前代第 k+1 步（块的边界结点可能是尾部主元）。

- 块并行段：可以完全融合。
- 尾部连通块：没有任何块会更新它的，可以直接融合；其余的要等相关的块做完前代再补做。线上用例 99.6% 在尾部，块很少，绝大多数连通块属于前一种。

### 4.3 一步的算法（第 k 步 → 第 k+1 步，每个网）

两个向量：`x` 放第 k 步的解，`w` 放第 k+1 步的工作向量。两者必须分开：块回代第 k 步要读尾部和 core 结点的 $x_k$，块前代第 k+1 步会改写这些位置的 `w`。

另外有两份按内部顺序存放的数据：`cdiag[v] = C_v/h`，以及电流源列表（内部位置）。

```
① core 求解（第 k 步）：w[core] → x_k[core]；
   随后 w[core] = cdiag·x_k + I_{k+1}（core 结点的 b_{k+1}，等待累加）
② 尾部连通块，并行，每块一个线程：
     a. 回代第 k 步（读 w[v_i] 中的 s_i 和邻居的 x，写 x[v_i]）
     b. w[v] = cdiag[v]·x[v] + I_{k+1}[v]（本块结点）
     c. 不受块影响的：立即做第 k+1 步前代（对 core 的更新放进延后缓冲区）；
        受块影响的：标记，留到 ④
③ 块并行段，并行：回代第 k 步 → 算本块结点的 b_{k+1} → 前代第 k+1 步
④ 补做 ② 中标记的尾部连通块的第 k+1 步前代
⑤ 按消元顺序把延后的 core 更新补减到 w[core]；回到 ①
```

每一步都要输出全部结点的电压，所以写回保留，但可以并入回代：每个结点的电压一算出来，就直接写到用户顺序的位置上，省掉单独的一遍。

### 4.4 接口草案

```c
vsdlss_status vsdlss_m3_transient_create(const vsdlss_m3_factor *F,
        const double *cdiag /* C_v，用户顺序 */, double h, vsdlss_m3_transient **T);
vsdlss_status vsdlss_m3_transient_start(vsdlss_m3_transient *T, const double *b0);
vsdlss_status vsdlss_m3_transient_step(vsdlss_m3_transient *T,
        csi nsrc, const csi *src_node, const double *src_val);   /* 电流源：稀疏列表 */
vsdlss_status vsdlss_m3_transient_get(const vsdlss_m3_transient *T,
        csi nidx, const csi *node, double *out);                 /* 全部或部分结点 */
void vsdlss_m3_transient_free(vsdlss_m3_transient *);
```

现有的 `vsdlss_m3_solve` 保持不变。新接口复用现有的分解、低度消元和 core 求解。

### 4.5 正确性

- 每条记录的算术和现在相同；依赖由 4.3 的顺序保证。
- 对 core 的延后更新仍按消元顺序补减。
- $b_{k+1}$ 的计算方式（先乘后除，还是先算 $C/h$）要和仿真器现在一致。对齐之后，新接口的每一步结果可以和"逐步调用 `vsdlss_m3_solve`"逐位比对，这作为回归测试。

### 4.6 实施步骤与估算（未实测，按读取量的比例推算）

| 阶段 | 内容 | 每步（现在约 165 ms） | 工作量 |
|---|---|---|---|
| P1 | 新接口；全程使用内部顺序；电流源用稀疏列表；b 在内部单独算一遍 | 约 130 ms（省掉收集和仿真器组装；写回保留） | 约 1 周 |
| P2 | b 在回代时顺手算出；写回并入回代 | 再省几 ms | 小 |
| P3 | 块并行段融合 | 合成数据上明显，线上用例影响小 | 约 1 周 |
| P4 | 尾部连通块融合 | 约 90–100 ms | 约 1 周 |
| P5（可选） | FP32 因子 | 约 70 ms | 1–2 周 |

每个阶段都和逐步求解对比结果和速度，在服务器上逐项做 A/B 验证。

### 4.7 前提条件

| 条件 | 状态 |
|---|---|
| 电容接地（C 对角） | 已确认；同一网内结点之间的耦合电容数量待查网表确认（VDD 与 GND 之间肯定没有，否则两网不会分成两个连通分量） |
| 步长 h 固定 | 已确认 |
| 电流源形式 | 每步给出"结点号 + 值"的稀疏列表 |
| 输出 | 每步全部结点的电压 |
| b 的计算公式和电容数据（用于逐位验证） | 待提供；没有时先用合成数据验证 |

如果确实有少量耦合电容：两端在同一连通块内的，融合照常；跨块的，这些结点的 $b_{k+1}$ 等两边都回代完再算，相应前代推迟到最后补做。

## 5. 其他更大的方向（未展开）

- **减少时间步数**：梯形法、Gear2，或指数积分器（MATEX 等）。需要改仿真器的时间积分，潜力可能是数倍。
- **GPU**：带宽高一个数量级，但右端项和解每步都要过 PCIe，必须把整个时间推进放到 GPU 上才划算。
