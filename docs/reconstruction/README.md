## 目标与边界

根据反编译证据恢复可理解、可验证、可持续维护的稀疏直接求解器。先恢复数学行为，再逐步恢复排序、分块和文件协议。函数同名、编译成功、某个样例运行成功均不能证明原版兼容。

实际项目路径是 `D:\vsdlss\vsdlss_solver`，反编译目录为 `reference/funcs`。用户给出的 `D:\vsdlss\vsdlss\_solver\reference\funcs` 在当前环境不存在。

## 阅读顺序

1. [原理和证据](01-principles-and-evidence.md)：两条原始路径、数学原理、数据布局、证据边界。
2. [现有实现审计](02-existing-code-audit.md)：已发现的问题及优先级，不重复采用旧 README 的完成声明。
3. [重建设计与阶段验收](03-design-and-roadmap.md)：建议的首阶段接口约定、分层和可检验标准。
4. [续接状态](CONTINUATION.md)：已做事项、未完成事项和下一次应从哪里开始。
5. [函数清单](function_inventory.csv)：688 个文件的符号、地址、大小字段、行数及 SHA-256。

清单由文件头和实际文件生成；`size_hex` 保留原始十六进制字段，`lines` 按换行分割计算（可能含文件末尾空行）。清单不是完成率，`review_status` 默认表示尚未逐个验证；本轮仅审计本文明确列出的关键函数。

## 证据规则

- **直接观察**：写明本地源文件、函数和关键表达式，可在当前快照复查。
- **算法解释**：给出数学推导；不能把标准算法当作原版逐行实现证据。
- **待恢复**：记录缺失字段、常量、调用目标或测试条件，不猜出一个类型便当成事实。
- **运行证据**：必须记录构建命令、环境、退出码、测试数据和误差。当前没有本轮运行通过的结论。
