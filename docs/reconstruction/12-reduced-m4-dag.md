# M4 预处理复用与超节点 DAG

日期：2026-09-11；基于 small-kernels 分支。

## M4 组合因子

新增 factorize_m4_reduced / m4_reduced_solve / m4_reduced_free。与 M3 共用 factorize_shared、factor_component、solve_component，未复制低度消元算法。规范化 → 独立分量 → 动态 0/1/2/3 度预消元 → 核心 M4 因子 → RHS 缩减 → 核心求解 → 恢复 → 全局散回。空核心无需磁盘文件；允许任意 RHS 和原地求解。发布因子/输出仍为事务式。

组合因子拥有分量映射、缩减记录和每个非空核心的 M4 因子；释放逐一关闭磁盘对象。各分量依次分解/求解，同一组合因子不支持外部并发调用。禁止把组合因子传给 M3 多 RHS 并行入口。M4 子因子处理核心排序，公共恢复层不重复应用排列。

`disk_budget` 是全部磁盘子因子 workspace_bytes 之和的上限：剩余预算按剩余非空核心数量分配，扣除实际占用后继续。该策略保守，不保证找到所有可行的非均匀预算分配。预处理结构、缩减记录、核心矩阵、恢复向量以及 runtime/分配器开销不在该预算内，不是进程 RSS 上限。这是本阶段明确边界，尚未达到全流程内存预算设计。

旧 M4 v2 单因子的 save/open 保持原义。组合因子的保存/重开尚未实现；CLI 拒绝 --m4-reduced 与 save/load/block-cols 组合。

使用：

```
./vsdlss_solver --m4-reduced --disk-budget 1048576 --threads 4 job
```

## 内存超节点数值分解 DAG

新增 factor_dag，作用于 M3 核心的超节点数值分解。按原始源超节点顺序生成同级 OpenMP 任务：

- F(s)：对源面板 token[s] 施加 inout 依赖，等待所有入向更新。
- U(s,t)：读取 token[s]，对 token[t] 施加 inout 依赖；等待源分解，并与其他写同一目标的任务串行。
- 目标分组由实际外部列所属超节点决定，不将同层树节点视为天然无冲突。

任务独占目标面板，贡献按源编号次序累加，因而保留串行数值顺序。不同目标和满足依赖的分解任务可并行。任务状态也由目标 token 保护；错误沿依赖传播，taskwait 后统一释放，失败不发布因子。外层已活跃并行时仍抑制嵌套；单线程和单超节点沿用原路径。

此处实现的是内存数值分解 DAG，不含回代 DAG、排序/符号 DAG、M4 磁盘任务并行或异步 I/O。辅助 owner/token/state 是 O(n+超节点数)；OpenMP runtime 的任务元数据随依赖边数增长，目前未实现有界队列限流。不能宣称相较原版相同调度策略或任意矩阵加速。

## 验证

test_reduced_dag：孤立点、带尾节点 K5、两节点链混合，空/非空核心，五种排序、多次 RHS、原地求解、NaN 失败输出保护、零预算失败。8³ 单连通 SPD 网格的多个超节点在 2/4 线程下与串行因子及解逐位一致，后向误差 <1e-12；非正定失败不发布因子。现有完整回归保持 M1/M3/M4 因子和残差对照。

专项 ASan/UBSan 已运行；不宣称 LeakSanitizer 或有效 OpenMP ThreadSanitizer 检查完成。数值一致测试不能代替 race checker。专项输出中的计时是单次观察，不是正式加速结论。

## 调度性能门槛

512 阶、448 个超节点的单次专项观察：串行 4.864 ms，DAG 2 线程 35.932 ms、4 线程 46.217 ms。任务粒度太细带来明显退化，故 DAG 默认关闭，须调用 vsdlss_set_dag_enabled(1)，或使用 `--m3 --dag --threads 4` 显式开启。该选项只控制内存数值 DAG，对 M4 磁盘路径无效。不宣称 DAG 已完成性能验收。下一步必须实现任务合并/限流并重新测量。
