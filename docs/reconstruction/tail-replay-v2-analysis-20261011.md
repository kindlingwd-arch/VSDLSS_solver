# main 尾部回放：开发前代码与算法分析

分析基准：`origin/main = 0234642`，2026-10-11。开发分支 `optimize/replay-tail-v2` 从此提交创建。本文在修改求解代码之前保存。目标仍是原串行回代时间的 1/8；文献中的倍数不作为本项目验收结果。

## 1. 现有运算及正确性约束

`src/vsdlss_reduction.c:forward_range/backward_range` 对消元记录 i（顶点 p、度数 d≤3、邻居 n_j、系数 m_j、主元 D_i）执行：

```
forward:  s = work[p]; saved[i] = s (可选)
          work[n_j] -= m_j * s                  j = 0..d-1
backward: v = (saved[i] 或 x[p]) / D_i
          v -= m_j * x[n_j]                    j = 0..d-1
          检查 isfinite(v); x[p] = v
```

因此不能把除法换成预存倒数乘法，不能对邻居求和进行树形归约，也不能使用 FMA 合并原来独立舍入的乘法与减法。并行化只改变互不冲突记录的执行时间；每个输出的运算链和舍入顺序必须保持。

`level_tail` 遍历原尾部的消元顺序，维护每个顶点最近一次触碰的层：

`L_i = 1 + max(last[p], last[n_0], ..., last[n_(d-1)])`。

随后把记录触碰的全部顶点的 last 写成 L_i。这比单纯的回代读依赖更保守：同层的任意两条记录既不共用主元，也不共用邻居，因而前向 scatter 不会竞争，同一顶点的不同减法仍保留原顺序。回代中同层输出之间亦无读写依赖。层内记录可按任意顺序处理或放入不同 SIMD lane。`uint16_t` 层号达到限制时安全退回无计划路径。

分层时间 O(N+R+E)，last/lv 临时数组约 2N+2R 字节（N 节点、R 尾部记录、E≤3R 个邻居）。`tail_order` 再按首个更新者排序，保留邻接局部性；`pack_tail` 直接按最终顺序打包，并行首次写入。求解顺序重编号后 `head` 替换为 `deg`，主元地址隐含为 k0+i。它们已在 main 中，不能把这些已有优化再计作本轮收益。

## 2. 当前执行路径和成本

当前 `TAIL_CHUNK=32`。层目录存 chunk 边界，chunk 存记录/邻居前缀偏移，各为 64 位整数。`backward_tail` 的持久 OpenMP 团队每层使用 `omp for schedule(static)`，每个 chunk 再调用 `backward_range`。32M 条尾部记录大约产生 1M 个这样的区间调用。区间内每条记录读取 degree、递减邻居偏移、分支循环 0..3 次、执行标量除法和有限性检查。具体各成本占比尚没有硬件计数器证据，不把源码观察直接当成测得的瓶颈比例。

按平均度数 2，重编号后的主元和系数数组流量至少 `(1+8+2*(4+8))*R = 33R` 字节，加上主元 RHS 读写和邻居 x 读取；32M 记录仅这部分就约 1.06 GB/回代。真实内存流量还取决于 cacheline、缓存命中、写回及 NUMA。因此线程数增加不会自动线性增加速度。

主线程依据 `min(requested, floor((R/levels)/tail_grain))` 限制尾部团队（默认 grain=2048）。平均 48K/层时上限约 23 线程，而非请求的 32/64。每层仍需屏障；666 层即每次回代 666 次。main 的提交注释记录服务端整次 solve 325→285 ms，但没有本机复现和原始日志，不能当成本轮数据。

前向 `tail_fwd` 已经按每层目标顶点做两趟 radix 排序，保存 target/source/multiplier（16E 字节额外持久内存）。同层目标互异，按目标排序减少散写。`VSDLSS_TAIL_PLAN=0` 则回到 chunk 路径。改进回代不需要再复制系数为完整新格式，避免增加数百 MB。

## 4. 本轮选定的有限范围方案（已获用户确认）

1. 每层每个线程领取连续 chunk 区间，在同一层内合并 scalar 区间；继续保留层末屏障，使用运行时实际团队人数计算边界。无新任务图，无每条记录原子操作。
2. 可选的每 chunk 1 字节同度数标记（0..3；混合为其他值），构建时一次扫描。32M 记录约 1 MB。标记分配失败时仍能正常求解。
3. 仅对重编号、同层、同度数的 chunk 使用 AVX2：lane 表示不同记录，使用真实向量除法，再按 j 原顺序乘减；d=2 将原交错数组在寄存器内解交错，不复制整份系数。非 AVX2、`VSDLSS_SIMD=0`、非重编号和混合度数均走标量路径。
4. 未分层的顺序区间仍有真实依赖，绝不能调用上述独立记录向量内核。
5. 增加内核随机长度/余数、0..3 度、saved/原地输入、NaN/Inf/溢出及符号零验证；沿用现有 OOM、非重编号、无前向计划、整次 M3 求解与残差测试。

该方案计算量仍 O(R+E)，持久元数据仅 O(R/32)，solve 不分配新内存。它针对区间开销和标量内核，无法消除流量下限，8 倍必须实测。

## 5. 计时与验收

当前 main 基准的缺点：两变体固定先后、只检查最后一次、忽略返回状态、只输出两位小数、首个线程数未必为 1、没有显示实际尾部团队。原始日志保持不改。

优化前先保存 main 的 bench_tail 可执行文件；改进后的基准测量工具分别链接相同编译选项的 main 与新代码。每次 RHS/reset 在计时外；预热；交替变体运行；逐次检查前向和回代输出；记录返回状态、实际团队、min/median/max、完整 replay 总时间。另用真实 M3 solve benchmark 测量包括核心求解和映射的整次 solve，并校验残差。replay 计时不得冒充整次 solve。

8 倍门槛：同一机器、同一输入、同一线程配置、相同编译参数下，`旧串行回代 median / 新回代 median >= 8`。另列 `当前 main 分层 median / 新版 median`，避免把已合入 main 的收益重复计算。仅某个 microbenchmark 达标不能宣称真实 61M 用例已达标。

开发前本机：WSL2、i7-1260P，WSL 报告 8 核/16逻辑 CPU、12 GiB RAM、单 NUMA。默认 -O2 -std=c11，METIS=1，OMP_PROC_BIND=close / OMP_PLACES=cores / OMP_WAIT_POLICY=ACTIVE。

初测 2M 节点，尾部 1,958,156、43 层（平均45,539/层），11 次 median：旧串行 1 线程回代 25.02 ms，main 分层 8 线程 4.60 ms，比例 5.44；逐位一致。固定先后和系统波动限制此初测的可比性。见 baseline-2m.log，后续以交替对比结果为准。

真实用户矩阵、实际服务器和原始运行日志目前不在此工作区，最终报告须区分本机合成验证和服务端待验证。
