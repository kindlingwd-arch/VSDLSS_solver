# 2026-09-22 单次分解/求解效率：合并预处理、减少缺页、并行求解

接 [18](18-powergrid-preprocessing-20260922.md)。目标是客户度数分布（2287.5 万结点）下单次分解和单次求解的耗时。

## 默认排序改为 AMD

在这类矩阵上，AMD 的排序时间和填充都明显优于 MLD（全量：排序 1.8 s 对 43.5 s，nnz(L) 1.07 亿对 1.56 亿）。现在 `order=0` 和 `order=5` 都是 AMD，MLD 需要显式指定 `-p 4`。README、QUICKSTART、`vsdlss.h` 注释和命令行帮助都已同步。

## 改动

1. **连通分量与抽取合并**：`vsdlss_components_build_graph` 在求连通分量时顺带建出带数值的对称邻接表，同时记录 BFS 顺序。大分量不再从 CSC 抽取子矩阵，而是直接从邻接表按 BFS 新编号构造低度消元的输入（`vsdlss_reduce_prepare_graph`，各结点的表并行构造）。这样省掉了一遍对 A 的随机散射和一个中间 CSC。
2. **减少大数组分配和缺页**：
   - 输入已经规范化（列内严格递增）时直接使用，不再复制；上三角合法性检查改为并行。
   - 分量大小数组按分量个数增长，不再按 n 分配。
   - 邻接游标借用 `vertices`，新编号数组借用 `local_of`。
   - 分解前先准备好所有分量，再释放邻接图、规范化副本和不再使用的顶点映射，然后才开始消元。
   - 消元记录用完后收缩。
   - 全量分解的缺页次数从 227 万降到 201 万。
3. **求解并行化和工作区缓存**：
   - 分解结束时分配好求解工作区，挂在 factor 上，用原子标志占用。并发调用拿不到时自己分配，所以多线程同时调用求解仍然安全。
   - gather、scatter 和结果拷贝改为并行。
   - 前代/回代消元按分解时记录的 2^16 结点块并行回放，块外的剩余部分再串行处理。
   - 核心的超结点三角求解改为按消去树并行：子树并行，顶部串行。前代改用拉取形式，与原推送形式逐位相同。
   - `solve_many` 在只有 1 个 RHS 时直接走单次求解路径。
   - 以上改动不改变任何浮点运算顺序，所以 1/2/4 线程下结果逐位相同，与 `solve_many` 也逐位相同。

## 仍可继续的地方

- 连通分量这一阶段（5.6 s）现在是最大的一项，主要花在 BFS 本身和建邻接表，都是串行的。可以改为并行的标签传播或并查集求分量，但要保证分量编号和 BFS 顺序与线程数无关。
- 核心数值分解 3.8 s 在 2 线程下已接近饱和，要在更多核的机器上实测。
- 单次求解中 gather/scatter 和两遍消元回放合计约 0.7 s，基本受内存带宽限制。如果调用方能直接提供按分解内部编号排列的 RHS，可以省掉 gather/scatter，这需要新增接口。
