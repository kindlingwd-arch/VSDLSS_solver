# 排序阶段：最小度的复杂度修复与 AMD 实现（2026-09-13）

分支 `codex/relaxed-supernodes-20260913`。动机与测量依据见
[14-cross-solver-comparison.md](14-cross-solver-comparison.md)：
对照 CHOLMOD 之后，差距的 64% 落在排序 + 符号，而不是数值内核。

## 一、`vsdlss_min_degree_order` 的 O(n³)

选主元循环里有这么一段：

```c
for (vertex = 0; vertex < A->n; ++vertex) {
    ...
    csi prior; int used = 0;
    for (prior = 0; prior < step; ++prior) used |= order[prior] == vertex;
```

**对每一步的每一个候选点，线性重扫一遍已消去的顶点表**，于是选主元是 O(n³)。
n = 10648 时约 1.2×10¹² 次比较。

顺带两处等价性观察，使修复可以做到输出完全不变：

- `graph_add_edge` 对 `a == b` 直接返回，所以这个图里**从不存在自环**，
  原来的守卫 `degree > 0 || !has_edge(v, v)` 恒为真，唯一起作用的过滤就是
  那个 `used` 重扫；
- `vsdlss_graph_degree` 对 `active[v] == 0` 的顶点返回 0，而度只会因为
  "刚消去的顶点的邻居"而改变。

因此把 `used` 换成 `eliminated[]` 数组、并只对刚消去顶点的邻居刷新度缓存，
选主元规则（最小度，同度取最小编号）逐字未变，排列结果逐位相同。

| n = 10648 | 修复前 | 修复后 |
|---|---:|---:|
| `vsdlss_min_degree_order` | 231.99 s | 13.24 s |
| 结果 `nnz(L)` | 1,401,238 | 1,401,238（不变） |

## 二、为什么 13 秒仍然不够

剩下的代价是算法本身的：`vsdlss_graph_eliminate` 把主元邻居之间的团
**显式建出来**，每次消去 O(d²) 次二分查找加有序插入。这是精确最小度的
固有开销，不是实现瑕疵。SuiteSparse 的 AMD 在同一矩阵上是 0.0058 s——
差 2000 倍。

## 三、`vsdlss_amd_order`（新增，order 5）

新实现采用商图（quotient graph）形式，即 Amestoy–Davis–Duff 的 AMD
（*An Approximate Minimum Degree Ordering Algorithm*, SIAM J. Matrix Anal.
Appl. 17(4), 1996）：被消去的主元变成一个**元素**，它的团由该元素代表而
不是由边代表，于是**填充边一次都不写出来**。变量的邻接表变成"元素表 +
变量表"，全部放在一块工作区里，空间不够时做垃圾回收。

配套的三个装置缺一不可：

- **近似外部度**：真实度需要对变量的各个元素求并集；改用基于**集合差**的
  上界，度更新才是邻接表长度的线性量级；
- **超变量**：邻接表相同的变量用哈希检出并一起消去——这同时也是数值阶段
  想要的宽超节点的来源；
- **元素吸收（含 aggressive absorption）与 mass elimination**：阻止商图膨胀。

选主元用的是近似度，所以排列与 order 3 的精确最小度不同，两者在填充上
互有胜负。**两条路径都保留**：order 3 仍是与反编译证据对应的精确重建，
order 5 是这一条。

### 与 SuiteSparse AMD 的对照

`test/bench_cross.c` 之外另有一个排序对照工具（见下方复现），
在同一矩阵上跑我们的实现与 `amd_l_order`：

| n = 10648 | MLD（当前默认） | AMD（本实现） | AMD（SuiteSparse） |
|---|---:|---:|---:|
| 排序耗时 | 0.1912 s | **0.0054 s** | 0.0058 s |
| `nnz(L)` | 1,763,500 | 1,315,142 | 1,273,997 |
| 后续 `sn_analyze` | 1.6028 s | 0.0792 s | 0.0690 s |

比 MLD **快 35×、填充少 25%**；耗时与 SuiteSparse AMD 持平，填充在其 3% 以内
（差异来自 tie-break 与 dense 阈值的取法）。n = 5832 时本实现的填充
（481,432）略优于 `amd_l_order`（488,275）。

注意第三行：符号分析快 20× **不是**符号阶段又改了什么，而是填充变少的
直接后果——`update_target` 的规模是 Σ|Rₛ|(|Rₛ|+1)/2，对填充极其敏感。

### 测试

`test/test_amd.c` 覆盖商图里容易漏测的几条路径：孤立顶点（初始度 0）、
超过 dense 阈值的稠密行、会塌缩成一个超变量的团、mass elimination，
以及一个大到必然触发工作区垃圾回收的 12³ 网格。每个形状都检查排列是双射、
两次运行结果相同（确定性）、以及 M1/M3 两条路径解出来的后向误差 < 1e-12。
ASan/UBSan 全绿。

## 四、端到端

22³（n = 10648）、同一台 2 核机器、交错运行取最小值：

| 状态 | 1 线程 | 2 线程 |
|---|---:|---:|
| `main`（起点） | 2.077 s | 2.029 s |
| + 并行效率轮（符号并行、分块内核、左视 DAG） | 0.902 s | 0.695 s |
| + 松弛超节点合并 | 0.483 s | 0.406 s |
| + AMD 排序（`-p 5`） | **0.247 s** | **0.197 s** |
| **累计** | **8.4×** | **10.3×** |

对 CHOLMOD 的差距（analyze + factor，1 线程）：

| n | 本分支 | CHOLMOD | 倍数（此前） |
|---|---:|---:|---:|
| 5,832 | 0.0835 s | 0.0163 s | 5.1×（11.5×） |
| 10,648 | 0.2570 s | 0.0450 s | 5.7×（12.2×） |
| 17,576 | 0.6681 s | 0.1541 s | 4.3×（8.3×） |

22³ 上本分支的 `nnz(L)` 是 1,243,250，**少于 CHOLMOD 的 1,315,142**
（我们在排序前还做了度 0–3 预消元）；26³ 上 CHOLMOD 自动切到 METIS，
填充反超我们（2,184,062 vs 2,618,482）。
整条流水线（0.257 s）现在也**快于 CHOLMOD 自己的单列数值阶段（0.408 s）**。

## 五、瓶颈已经换位

22³、AMD + 松弛超节点、1 线程：

| 阶段 | 耗时 | 占比 | 此前（MLD + 严格） |
|---|---:|---:|---:|
| 排序 | 0.0056 s | 3% | 0.2426 s |
| 符号分析 | 0.0730 s | 29% | 0.5418 s |
| **数值分解** | **0.1696 s** | **67%** | 0.2877 s |

排序从 44% 降到 3%，**数值阶段现在是主导项**。而且超节点更宽了
（max_width 787，此前 570），工作量从"外部块更新"移到了"面板分解"
（panel 0.462 GF vs update 0.305 GF，此前是 0.245 / 0.515）——
这正是 BLAS-3 最吃得下的形状。

当前数值速率 4.5 GF/s，CHOLMOD 超节点 16 GF/s。把宽面板交给
dsyrk/dgemm/dtrsm/dpotrf，预计可把 22³ 的 0.257 s 压到 0.13 s 上下，
即再快约 2×，落到 CHOLMOD 的 3 倍以内。**这一轮之后，"把浮点运算压进
BLAS-3"才真正是收益最大的下一步。**

## 六、默认排序未改

`-p 0` 仍然是 MLD。虽然 order 5 在这批测试矩阵上全面更优，
但 MLD 是与反编译证据对应的重建产物，默认值的变更应当单独决定，
并配一批更宽的测试矩阵，而不是顺手改掉。
