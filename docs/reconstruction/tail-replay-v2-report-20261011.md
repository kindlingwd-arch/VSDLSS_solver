# main 尾部回放优化：实现与验证报告

基于 main `0234642`，分支 `optimize/replay-tail-v2`。本轮先保存代码与文献分析，再按用户确认的范围开发。开发前分析见 `ANALYSIS.md`，仓库内副本为 `docs/reconstruction/tail-replay-v2-analysis-20261011.md`。

PR 发布时远程 main 已更新到 `85792d2`（新增默认关闭的 `VSDLSS_CHAIN_ORDER=1`）。本分支已更新到该版本；本文性能数据仍以 `0234642` 为对比基准，未针对链连续编号功能重新计时。PR 发布前另在新基准上执行全套测试，以及开启链连续编号时的 M3/重编号检查。

本 PR 附带的最终性能原始日志、CSV 与发布前检查日志位于 [tail-replay-v2-results](tail-replay-v2-results/README.md)。开发期其余本地探索日志未作为最终性能验收数据发布。

结论：实现及数值验证通过，本机合成用例存在部分配置收益，也存在退化；**8倍回代目标未达成，保留为优化候选**。不能据此宣称用户真实用例或所有线程配置均已加速。

## 实际实现

`backward_tail` 保留原有层顺序及层末屏障，依据 **OpenMP 实际团队人数**划分线程内连续 chunk 区间。标量路径把多个 32 条记录的小区间合成一个范围，减少调用、边界及调度开销；不改变记录内 `rhs/pivot` 后按邻居顺序逐项乘减的运算链。

构建层目录时一次扫描，给每个 chunk 添加可选的 1 字节同度数标记。相邻同度数 chunk 在同一线程、同一层内合并；重编号后的 degree 0..3 区间使用 AVX2，四个 lane 分别计算四条独立记录。degree 2 的交错邻居与系数在寄存器内拆开，使用原系数数组和真实除法，不复制整份系数，不使用倒数乘法或 FMA。非有限结果仍返回原错误状态。混合度数、未重编号、非 AVX2、关闭 SIMD、标记分配失败均保留标量回退。

无前向计划时的 `forward_tail` 也合并线程连续范围；main 已有的按目标排序前向计划保持原有运算。求解阶段不增加内存分配；新增持久内存约为每 32 条记录 1 字节，3200 万记录约 1 MB。整体复杂度仍为 O(R+E)。

分层中的互斥触碰保证同层 SIMD lane 无读写依赖，前向写入顺序与回代每个结果的舍入链保持原样。打包路径原有节点数限制为 2^30，因此 AVX2 有符号 32 位 gather 的索引范围有效。

## 测量方法

main 快照只替换两份 benchmark 源码，生产求解代码保持 `0234642`。main 与新版使用相同 GCC 9.4、`-O2 -std=c11`、OpenMP、METIS=1。两侧 benchmark 文件 SHA-256 相同。

环境为 WSL2 / i7-1260P，WSL 报告 8 核、16 逻辑 CPU，12 GiB 内存、单 NUMA；设置 `OMP_PROC_BIND=close`、`OMP_PLACES=cores`、`OMP_DYNAMIC=FALSE`、`OMP_WAIT_POLICY=ACTIVE`、`GOMP_SPINCOUNT=30000`。这不是用户生产服务器。

每个线程配置预热两次，21 次计时；同一进程内交替串行尾部与分层尾部，进程顺序为 main、新版、新版、main（ABBA）。使用单调时钟，RHS/reset 在计时之外。前向与回代相邻计时，随后逐次检查回代；前向检查另外执行，避免在两段计时之间扫描完整向量而改变缓存状态。分别保存实际线程人数、min/median/max、前向加回代的每次总时间的 median。

两次进程的 median 用范围展示；表中汇总数是两次进程 median 的平均（两个数的 median），不是 42 次样本混合后的 median。小数位表示输出精度，不表示系统噪声低至该量级。原始日志保留所有极值。

## 回放对比

200 万节点合成用例：尾部 1,958,156 条，43 层，平均 45,539 条/层；99.9% 消元记录在尾部。所有逐次输出逐位一致。

| 实际线程 | main 回代 median 范围 / ms | 新版回代 median 范围 / ms | 新版相对 main |
|---:|---:|---:|---:|
| 2 | 8.140565–9.260891 | 5.073241–5.187929 | 约 1.70 倍 |
| 4 | 4.697206–5.993978 | 3.470549–3.501825 | 约 1.53 倍 |
| 8 | 4.936084–5.901418 | 4.634312–4.806543 | 约 1.15 倍 |

800 万节点合成用例：尾部 7,840,098 条，46 层，平均 170,437 条/层，123 个并行块。所有逐次输出逐位一致。

|---:|---:|---:|---:|
| 2 | 52.165401–52.672125 | 37.105620–39.836808 | 1.36 倍 |

8 线程汇总回代慢约 3.9%，两侧进程 median 范围部分重叠；无法证明该配置有稳定改善。新版在该用例相对原串行的最佳为 3.60–3.69 倍，仍未通过 8 倍门槛。8 线程前向加回代总时间汇总 main 68.618618 ms、新版 70.596994 ms，慢约 2.9%。这组结果要求在服务器上继续评估收益与退化，不能将本轮称为普遍加速。

## 完整求解与 SIMD 消融

另一个 200 万节点、degree 直方图匹配的合成 PG 用例，nnz_upper=4,110,394、核心 135,049 节点、核心 L 约 5.4M 非零。一次因子分解后各配置两次预热、15 次完整 solve；同样采用 ABBA 进程顺序。该图与前面的 wires replay 图不同。结构诊断发现尾部仅 103,965 条/74 层，平均 1404 条，低于 grain=2048 的门槛，**未启用本轮尾部分层内核**。这组作为完整求解正确性验证和计时负对照，不作为本轮目标路径的性能验收。

|---:|---:|---:|
| 1 | 43.708180–48.524519 | 40.289983–41.775384 |
| 2 | 29.239413–29.378901 | 27.912181–32.139053 |
| 4 | 21.953186–23.513710 | 21.656069–26.230854 |
| 8 | 20.357583–21.631788 | 21.671817–21.905664 |

8 线程汇总 main 20.994686 ms、新版 21.788741 ms，相差约 3.8%；1 线程也出现明显差异。由于这组未执行新内核，这些差异不能归因于尾部代码；它们显示本机进程间噪声不可忽略。内部顺序接口另有独立记录，未混入完整 solve 计时。

全部样本分别与单线程参考逐位比较，四次进程最终解哈希均 `f5cc992637f756ad`，后向误差均 `1.542163e-17`；内部顺序接口每次映射回原编号后也逐位相同。数据见 `fullsolve-*.log`。

对新版 200 万 wires 用例按 SIMD=0、1、1、0 另做 ABBA：

| 实际线程 | 合并标量区间（SIMD=0）回代 median / ms | 同一实现开启 SIMD 回代 median / ms |
|---:|---:|---:|
| 4 | 3.874536–4.715576 | 3.710025–4.014013 |
| 8 | 4.948763–5.088658 | 4.590921–5.103237 |

汇总比值约为 1.11 倍和 1.04 倍，但范围重叠，SIMD 的增量收益较小且存在系统波动。不能把本轮全部收益称为向量化收益。数据见 `ablation-*.log`；全部数值检查通过。

覆盖率诊断：200 万 wires 的同度数 chunk 覆盖 1,957,551/1,958,156 条（99.97%）；800 万为 7,839,115/7,840,098 条（99.99%）。因此大图收益有限并非大量混合 chunk 未向量化造成。缓存/内存流量、gather、除法、线程亲和性与屏障是待进一步测量的因素，当前没有硬件计数器证据把耗时比例分配给它们。诊断数据见 `coverage-2m.log`、`coverage-8m.log`。

补充的 `bench_tail_solve` 直接用 wires 图执行真实 M3 因子分解及完整 solve。M3 前置排列使 200 万图的实际尾部变为 1,313,839 条/293 层，平均 4484 条，默认 grain 将尾部团队限制到 2。基准验证已重编号、固定 grain=2048，使用相同 GNU ld 外部 wrapper 在每个 replay 入口重置线程观察，再分别记录前向/回代尾部实际团队；核心求解的较大团队不会冒充尾部团队。两版均包含相同的少量 TLS 读写计时开销，生产求解源码没有为计时改动。该基准亦逐次比较参考解、校验残差和哈希。

这个结构差异来自真实调用链：`vsdlss_factorize_m3 → prepare_component` 对大分量采用已有 BFS 顺序，通过 `vsdlss_reduce_prepare_graph` 建立输入，再由 `factor_component → vsdlss_reduce_run_packed` 消元。直接 replay 基准则在原随机编号上使用 `vsdlss_reduce_prepare_csc`。编号改变块内局部消元量、尾部记录数和依赖层，因此同一矩阵的两个基准也不能假定团队数相同。BFS 和这些路径均是 main 已有行为，本轮不更改它们。

## 正确性与构建验证

- 默认 METIS=1 全套测试通过，原有 I/O 测试的路径截断编译警告保留，未发现测试失败。
- `-O3 -march=native -Wall -Wextra -Werror -std=c11` 下内核、M3、重编号及关闭 SIMD 路径通过，逐位一致。
- 关闭 OpenMP 的相同测试通过。
- AddressSanitizer、UndefinedBehaviorSanitizer、泄漏检查下同组测试通过，退出状态 0。
- 新内核覆盖 0..65 条记录、所有向量余数、degree 0..3、saved/原地输入、散布邻居、NaN/Inf/溢出、符号零；手算链验证除法位置和减法顺序。
- 新紧凑尾部测试覆盖同度数/混合 chunk、三条记录的最后一层、线程空范围、可选元数据缺失、1/2/4 线程、saved/无 saved、非有限返回状态；沿用原有 OOM 和计划回退测试。

日志：`full-suite-final.log`（最终树）、`full-suite.log`、`check-native.log`、`check-serial.log`、`check-sanitize.log`、`bench-tail-solve-target-build.log`（正式构建入口，-Werror）。原有M5测试声明仅验证gate/replay、未验证其原格式兼容性，未扩大这个测试的证明范围。审查发现的“前向校验改变回代缓存状态”和“核心团队可能冒充尾部团队”问题已经修正；修正后重新计时。严格 C11 的 native 构建未复现浮点收缩导致逐位不一致的问题。

## 不纳入验收的数据

`baseline-*`、`initial-*`、`fair-*`、`stable-*` 均是探索性原始日志。部分使用早期 benchmark；后续发现另一组 `bench_phase far.bin` 工作流占用约 7 个 CPU 核，并连续启动新进程，另有前向校验插在回代计时前的缓存偏差。这些数值 **不用于最终收益或 8 倍判断**，包括早期出现过的单次 9.165 倍。

最终 `final-idle-*` 重新运行前，WSL 进程检查确认上述实验已经退出，系统负载恢复空闲；本任务各性能测试串行运行。没有暂停或终止他人的实验。

用户 3300 万/2809 万节点、666 层的原始数据和生产服务器仍未提供。本轮合成用例的层数、层宽与生产不同；完整 solve 也不能用 replay 的时间替代。8 倍目标需在真实用例上继续验证。

## 复测入口

本地结果目录中的 `run_compare.sh` 自动运行 ABBA 对比：

```sh
bash run_compare.sh 2000000 21 "1 2 4 8" 20 200 final-idle-2m
bash run_compare.sh 8000000 21 "1 2 4 8" 20 1000 final-idle-8m
bash run_fullsolve.sh
bash run_ablation.sh
bash run_active_fullsolve.sh
```

`verify_variants.sh` 保存三组编译选项与验证流程。仓库内可通过 `make METIS=1 bench_tail_solve` 构建完整 wires solve 基准（GNU ld），默认使用 200 万节点、21 次样本。跨机器复现时先分别构建 main `0234642` 和本分支，并同步本分支两份原有 benchmark 及新增 `test/bench_tail_solve.c`；只更新测量工具。确保其他 CPU 密集任务退出，再记录实际团队、逐位一致和残差。

生产验收应同时记录：（1）旧串行回代/新版回代 ≥8；（2）当前 main 分层回代/新版回代；（3）包含核心求解与编号映射的整次 solve；（4）load、分层、重编号、计划建立的独立一次性时间。不能将已有 main 分层收益重复算成本轮增益。
