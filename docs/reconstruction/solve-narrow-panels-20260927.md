# 单 RHS 求解：7–31 列面板内核（2026-09-27）

环境：1 vCPU KVM（Xeon @ 2.10GHz，AVX2/AVX-512 可用，内核只用 AVX2），3.9 GB 内存，GCC 13.3，`-O2 -fopenmp`，无外部 BLAS。
用例：`bench_pg_profile` 的 800 万节点双网（平均度 2.5），AMD（order 5），分解与求解均 1 线程。
本机比 `solve-buckets.md` 的 8370C 慢（同配置完整求解 0.74 s 对 0.42 s），只比较同进程内的相对变化。

## 改动（结果与 `590190b` 逐位一致）

| 改动 | 位置 |
|---|---|
| 前代，宽度 7–511 的串行路径：外部行每 16/8/4 个驻留寄存器扫完全部列再写回一次（`vsdlss_simd_ext_update`）；绕过 generic 内核的 OpenMP 区域 | `vsdlss_panel.c: simd_fwd_narrow` |
| 回代外部点积：两组四列交错（`vsdlss_simd_dot8`），剩余 1–3 列用填充向量（`vsdlss_simd_dot_tail`），行向量由 128 位加载 + insert + 通道内 unpack 组装，不再用跨通道 permute | `vsdlss_simd.c`，`simd_back_narrow` |
| 运行时开关 `VSDLSS_SOLVE_V2`（bit 1 前代，bit 2 回代，默认 3；0 为原内核） | `vsdlss_panel.c` |

每个输出仍按原顺序做“乘积舍入、再相减”，向量通道只装不同输出，所以不改变任何舍入。

## 8M 结果（`bench_solve_v2`，同一因子，四种配置轮换，每次解逐位核对）

完整求解（`vsdlss_m3_solve`），逐轮配对比值的中位数：

| 配置 | 第 1 次（15 轮） | 第 2 次（21 轮） |
|---|---|---|
| 仅前代 | 0.900 | 0.904 |
| 仅回代 | 0.978 | 0.985 |
| 两者 | **0.900**（0.741 → 0.660 s） | **0.895**（0.744 → 0.666 s） |

按宽度桶单独重放面板内核（11 次中位数，ms）：

| 宽度 | 前代 原→新 | 回代 原→新 |
|---|---|---|
| 7–31 | 119.5 → 64.5（1.85×）/ 122.9 → 70.1（1.75×） | 87.1 → 83.1（1.05×）/ 89.4 → 84.5（1.06×） |
| 32–63 | 1.42× / 1.38× | 1.10× / 1.11× |
| 64–511 | 1.11–1.34× | 1.03–1.12× |
| ≥512 | 第 1 次 0.95×，之后该桶退回原路径 | ≈1.0–1.07× |

## 解释

- 前代收益约六成来自固定开销：generic 内核在单线程下也进入 `omp parallel ... if(0)`，微基准中宽度 7、外部行 0 的面板每次约 435 ns（新路径 62 ns）。其余来自寄存器驻留，外部行越多占比越高。
- 回代外部点积内核本身快 1.1–1.3×（dot8 对 dot4），但 7–31 列面板的回代主要受对角块回代的串行依赖链限制：为保持逐位一致，第 j 列必须先减去刚算出的 x[j+1]，整个三角块是一条长度约 w²/2 次减法加 w 次除法的延迟链。微基准中宽度 16、外部行 32 的面板，对角块约占回代一半。继续压缩需要改变累加顺序（不再逐位一致）或预打包布局，本轮未做。

## 适用范围与限制

- 前代改动只作用于串行路径（1 线程、`solve_batch`/`solve_many`、不走树调度的分量）。多线程树调度的前代用 `forward_pull`，本来就寄存器驻留、没有 OpenMP 区域开销；那里的收益只剩回代的约 2%。本机只有 1 个 vCPU，**多线程未测**。
- 合成拓扑，不是业务矩阵；单机单时段；重放是只跑一个桶的面板序列，存在缓存状态差异，只用于归因，不能与完整求解相加。
