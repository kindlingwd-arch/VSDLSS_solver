## 主要内容

见附件自带的 [20-vdd-gnd-components](20-vdd-gnd-components-20260923.md)。要点：

- **分量调度**：结点数不少于 n/(4T) 的分量算大分量，多个大分量按大小比例分配嵌套线程组同时处理，分量内部并行照常生效。此前只按分量数开线程、分量内部串行，两个分量时无论多少核都最多用 2 个线程——这是 VDD/GND 结构下的主要瓶颈。
- **消元记录压缩**：每条约 33 字节（原 72），分块消元直接写入线程私有暂存并就地压缩，不再分配 n×72 字节的记录数组。
- **求解流程**：先取齐所有工作区，局部阶段完成后才整体写回，失败时输出不变，且不再需要 n 长的全局暂存与最后一次整体拷贝。工作区直接接管低度消元已写过的数组，首次求解不再明显慢于后续。
- **透明大页**：8 MiB 以上的大分配调用 `madvise(MADV_HUGEPAGE)`，全量分解缺页由约 195 万降至约 55 万；`VSDLSS_NO_HUGEPAGES=1` 关闭。
- **连通分量并行**：度数统计与邻接填充按行区间分线程，填充同时其余线程跑无锁并查集打标签，随后各分量 BFS 同时进行。结果与串行逐位相同。**作者实测该项在 2 核虚拟机上没有收益**（行区间填充、并查集与填充重叠、两网 BFS 并行三种形式都不快于串行，原因是访存密集、第二个核带不来额外带宽），因此只在 3 线程及以上启用。
- 新增 `PG_NETS=2` 的 VDD/GND 双网用例（`make bench-pg-vddgnd`），总度数直方图与客户数据逐项相同，拆成 52% / 48% 两张结构不同的网。

## 与本地分支 `perf/components-parallel-20260922` 的关系

该分支（`66811c0`、`3327617`）实现的正是同一思路：填充邻接表时维护并查集，按最小结点号定根，各分量 BFS 并行，输出与串行逐位相同。**本次附件以更完整的形式覆盖了它**——无锁并查集、邻接填充按行区间并行、填充与并查集重叠在不同线程，并且附带了 2 核上的实测结论。

该分支从未编译过，且其文档占用编号 21（作者下一篇很可能用到）。建议废弃，不再合入。其中唯一未被覆盖的是连通分量阶段内部的分阶段计时打点（`components: adjacency` / `label+bfs` / `finalize`）；如果多核实测时需要看该阶段内部构成，可在当前 main 上单独重做一个小改动。
