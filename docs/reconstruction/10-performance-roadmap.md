# 求解器性能设计与实施清单

日期：2026-09-11。基线：panel-speed 分支，远端 1a40f01。

## 契约

仅实数 SPD、64 位索引、上三角 CSC。失败不发布新因子、不覆盖用户解；别名 RHS 保持可用。禁止截断指针 ABI。默认不引入外部 BLAS，不启用 fast-math。所有优化保留可比较的基线、排序和输入；微基准不能代替端到端验收。M4 数值预算与全流程 RSS 分别统计。

## 分阶段设计

### P0 观测与验收（待完成）

将规范化、分量、低度缩减、排序、符号、更新映射、数值分解、回代、I/O 分开计时。记录块宽 1–6/7–32/>32 分布、源/目标读取次数、实际线程数、峰值工作区。使用单调时钟；统计默认关闭，不在数值内循环加锁。测试集包含低度链、多个不等大分量、单分量三维网格、宽超节点和多 RHS。固定排序，1/2/4/8 线程各预热后至少五次取中位数；记录硬件和构建选项。

### P1 小块内核（本轮部分实施）

对宽度 1–6 提供固定宽度求解入口和展开内积，通用路径作为回退。固定宽度入口不等于编译器一定生成全展开机器码；必须检查汇编和基准。保持每个元素运算顺序。前代、回代、外部贡献、空外部行、非连续索引、NaN/Inf、非正主元及 RHS 别名需与通用内核逐位对照，并检查残差。未经性能门槛验证，不宣称提速。

### P2 M4 复用预处理（待实施）

新增统一预处理对象，拥有全局/局部分量映射、缩减记录与核心矩阵；M3/M4 共用。每个核心选择内存或磁盘因子；空核心直接恢复。RHS 按全局映射收集、缩减、核心求解、恢复、散回。保留旧 M4 v2 单核心 API；新组合因子使用独立容器版本，记录每分量映射、缩减记录和子因子目录，不把现有 v2 文件静默改义。

预算是所有同时驻留分量、缓存和恢复向量的总和；不能给每分量各发完整预算。首先串行分量处理，再按预算允许的并发数调度。验收包含消元后再次断开的核心、全消元、混合空/非空核心、多 RHS 和中途失败清理。

### P3 超节点任务图（待实施）

从实际因子列结构建立依赖，不能只按消元树同层无条件并行。分解任务等待全部入向更新完成；更新任务写独占目标块，或在私有贡献缓冲中计算并按固定源编号归并。不能让多个源并发直接写共享面板。任务成本考虑宽度、外部行数和更新数量；线程预算统一，禁止任务并行与 BLAS 满线程嵌套。内存预算覆盖待归并贡献；不足则限流。

验收：单大分量、多源共享目标、极不均衡树、失败传播、重复确定性及可用 OpenMP race checker；TSan 环境不兼容时不得登记通过。

### P4 大块 BLAS 后端（待实施）

独立构建选项 BLAS=none/openblas/mkl，默认 none。对大块使用 POTRF/TRSM/SYRK/GEMM，小块保留内核。核对 LP64/ILP64 与 csi 的转换边界。外层任务并行时后端单线程，后端内部并行时限制外层并发。不修改进程全局线程设置；后端无法满足线程契约时拒绝该组合。BLAS 改变舍入顺序，验收使用因子重构与后向误差，不要求跨后端逐位一致。

### P5 批量 RHS 与符号复用（待实施）

批量 RHS 采用列主序和显式 leading dimension，按内存预算分批。M4 每次读块服务整批 RHS；结果全部成功后提交。覆盖重叠/别名、步幅溢出和末批不足。

新增 analyze/refactor 分离 API：analyze 对象不可变、拥有规范化模式与排列；refactor 严格检查模式一致，创建新数值因子，失败保留旧因子。低度缩减结构与数值必须分离，不能复用旧乘子或主元。保存模式指纹只能加速筛查，最终须完整模式检查。

### P6 M4 缓存与异步读取（待实施）

先实现按块编号的有界缓存和 I/O 统计，再引入双缓冲预取。使用位置读取或独立句柄，不能跨线程共享可变 FILE 游标。缓存项有未加载/读取中/就绪/脏/失败状态；取消、释放先等待 I/O 完结。所有缓存计入预算，脏块只能在依赖允许时写回。验收包括短读写、取消、损坏、低预算、资源清理及读写次数减少。

### P7 部分分解与恢复（待实施，两个独立功能）

部分分解明确保留节点集合，输出 Schur 补及恢复算子；有公共节点的子域不能当作互不相关方程组。验收用完整求解比较保留节点和恢复解。

断点恢复采用新文件协议：输入/配置标识、排列、已完成块、校验和、提交序号。只在依赖闭合的安全点发布 checkpoint；临时写入、同步、原子发布，崩溃后忽略未提交尾部。完整因子 save/open 不等于断点恢复。测试必须在各写入边界模拟进程中断，验证重启结果。

## 执行顺序和停止条件

P0 → P1 验证 → P2；P3 与 P4 在 P0 确认数值阶段瓶颈后实施；P5 可独立推进；P6 依据 I/O 占比实施；P7 单独验收。每阶段都需提交代码、测试、原始 benchmark、数值误差和未完成事项。当前仅 P1 有代码改动，其余均未实现；本文件不是完成声明。
