# 2026-09-21 超节点数值核心重构（左视 + 相对索引）

分支 `refactor/left-looking-supernodal`，基于 main `ec35ee1`。目标：在不改公共 API、不改默认排序、不引入外部 BLAS 的前提下，清理 M3/M4 共用的超节点核心，并消除实测中的主要瓶颈。

## 重构前的瓶颈（同机实测）

26³ 网格（n=17576），单线程，各阶段拆分：

| 排序 | 排序 | 符号分析 | 数值分解 | 更新目标表条目 |
|---|---:|---:|---:|---:|
| MLD | 0.651 s | 1.365 s | 1.383 s | 171,427,072（≈1.37 GB） |
| AMD | 0.010 s | 0.189 s | 0.575 s | 11,463,273 |

1. 符号分析为每个源面板物化 `|R|(|R|+1)/2` 个更新目标槽（`update_target`），MLD 下的大分隔面板让它成为最大的时间和内存开销；还两次遍历 L 的全部条目（`ereach`），并在因子里复制 `l_row_index/l_panel_slot`（每个非零元 16 字节，是数值本身的两倍）。
2. 数值阶段是逐超节点的右视散射，每个超节点打开若干并行区；面板分解是非分块的列算法，1–3 GF/s。
3. MLD 排序中有多处 O(n²)：粗化的 coarse id 分配是双重循环，按度排序用插入排序，节点分隔器每个左顶点清零整个 `seen`，增益细化每轮重算所有顶点的增益，以及每次递归调用都做 O(n) 的初始化。
4. 面板数组由 `calloc` 延迟分配，首次触碰的 4 KiB 缺页散落在数值循环里；在这台 VM 上约 7 µs/页，占 30³ 数值时间的三分之一以上，而且让多线程几乎没有加速。

## 改动

### 符号分析（`vsdlss_supernodal_symbolic.c`，重写）

- 消元树 + 后序 + Gilbert–Ng–Peyton 列计数，不再遍历 L 的条目。
- 最大超节点判定：`parent(j)=j+1` 且 `|L(:,j)|=|L(:,j+1)|+1`，与旧的 memcmp 判定等价。
- 外部行 `R_s` = A 在该超节点列上的下三角模式 ∪ 子超节点的 `R`，逐个排序。
- 可选的宽松合并（`vsdlss_sn_analyze_relaxed`，M3 facade 默认使用）：子超节点是父超节点的最后一个孩子时合并，阈值沿用 CHOLMOD 默认值（≤4 列无条件；≤16 列零元占比 <80%；≤48 列 <10%；其余 <5%）。合并组保留顶端超节点的 `R`，下层成员的非模式位置存为显式零。
- 每个目标面板的源块列表（`blk_ptr/blk_src/blk_first/blk_end`），按源编号排序，固定了累加顺序。存储为 O(n + Σ|R_s|)。
- `vsdlss_postorder_permutation`：把消元树后序并入 `(q, pinv)`。填充不变，但保证链在列编号上连续，超节点更大。M3 和 M4 都在排序后调用它。

### 稠密内核（`vsdlss_dense.c`，新增）

- `vsdlss_gemm_nt_sub`：8×4 寄存器块（GCC/Clang 向量扩展），64 行 L2 分块，GNU ifunc 在 AVX-512/AVX2/基线之间运行时分派（`-DVSDLSS_NO_CLONES` 可关闭）。带带宽偏移参数 `tri`，只算/只写需要的三角部分，上三角保持为零（M4 块校验依赖此不变量）。
- 算术契约：每个输出元素 `acc=+0; acc+=a*b（k 递增）; C-=acc`，乘加分离（ISO C 模式不做 FMA 收缩）。因此结果与寄存器分块、CPU 分派版本、线程切分都无关，`test-kernels` 对所有尺寸和带宽偏移逐位对照标量参考。
- `vsdlss_dense_potrf_panel`：左视分块 Cholesky（NB=48），块更新走 GEMM，TRSM 按 32 行瓦片向量化；`vsdlss_panel_factor` 现在直接调用它，M3/M4 共用。

面板分解单独测量（1 线程）：64 列 2.3→6.1 GF/s，256 列 3.5→16 GF/s，1024 列 2.4→9.8 GF/s（旧 → 新）。

### 数值分解（`vsdlss_supernodal_numeric.c`，重写）

- 左视：每个目标面板一次完成“装配 A → 按源顺序减去所有源块 → 分解”。源行通过每线程的相对索引数组映射到目标行；源行在目标中连续时直接原地 GEMM，否则进 128×64 瓦片再散射。两条路径逐位相同。
- 调度：阶段 1 把工作量 ≤ 总量/(4·线程数) 的最大独立子树分给线程组（大的先分）；阶段 2 按后序处理树顶，线程在大 GEMM/TRSM 和大源块的行分块内部使用。每个面板看到的运算序列与线程数、调度无关，因此 1/2/4 线程的因子逐位相同（`test-supernodal`、`test-reduced-dag` 检查）。
- 旧的实验 DAG 开关不再有独立路径；多线程时总是使用上述树调度。`vsdlss_set_dag_enabled` 保留以兼容 API/CLI。
- 面板存储：≥8 MiB 时 2 MiB 对齐并 `madvise(MADV_HUGEPAGE)`，由线程组并行清零。
- 因子只保留 `column_start/row_ptr/row_index/panel_offset/panel`，每个非零元少 16 字节元数据。`vsdlss_sn_export_L` 从面板重建 CSC（宽松布局包含显式零）。
- `vsdlss_sn_solve_batch` + 新的 `vsdlss_m3_solve_many`：每个面板对一批 RHS 连续应用，RHS 按线程分组；逐 RHS 运算与单 RHS 求解相同。

### M4 磁盘路径

符号分析换成新的严格布局（加后序）；外部更新由逐元素 `panel_dot` + 二分查找换成 GEMM 瓦片 + 有序合并映射，按行瓦片并行。块格式、预算、I/O 次序不变。

### MLD 排序（输出逐位不变）

去掉上述 O(n²) 步骤：coarse id 两遍线性分配；按（度, 原编号）qsort，原编号唯一所以顺序与插入排序相同；分隔器用时间戳代替清零，`ml[v]` 由增广路径直接返回；增益细化和区域增长维护增量增益/连接权；子图构建共用一个 -1 工作数组并在返回前复原。另有 OOM 传播与原实现一致（分配失败扫描仍要求每个失败点返回 OOM）。

五个矩阵（2D/3D 网格、随机图）上的 MLD 排列哈希与基线逐位相同；排序耗时：22³ 0.303→0.086 s，随机 n=20000 2.69→0.30 s。

## 边界与后续

- 结果仍是单一合成矩阵族；真实应用矩阵、峰值内存和多次运行分布仍需补测。不要据此单独修改默认排序或线程策略。
- 默认排序仍为 MLD。30³ 上 MLD 排序已占分解时间的三分之一，而 AMD 的填充更少（5.74M vs 7.03M 含零）；是否切换默认值应单独决定。MLD 的下一步是质量（分隔器大小）而不是速度，可考虑 FM 边界细化与多次二分取优。
- 在这台 2 vCPU VM 上数值阶段已经接近稠密内核在内存带宽下的上限（单核缓存内 GEMM ~22 GF/s，实测数值阶段 12–14 GF/s）。继续提升主要靠：打包 A 的 GEMM（大 k 时）、树顶面板更细的任务并行、以及 M4 的块级预取。
- 宽松合并目前只用于内存 M3；M4 仍使用严格布局，避免改变磁盘块大小与预算行为。
